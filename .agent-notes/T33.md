## Observation: the jar rejects malformed <style> bodies (StyleParser errors are command errors)
- **Context**: T33, deciding whether the style body needs an exact grammar.
- **Finding**: `CommandStyleMultilinesCSS.executeNow` turns StyleParsingException into an error (:92-93), and IllegalStateException / NPE escape too (StyleParser.java:104, :112, :121, :153, :172). 88 oracle probes confirm. Rejected: a lone `{`, `Prop`, `Prop:`, `Prop red {`, `Prop *`, `*`, `,`, `:`, `:depth(1)` with `{` on the next line, `a,` then `b {`, a last line `} // c`, `@x` in a value, a tab inside `.foo<TAB>bar`. A `//` comment swallows the newline token, so the next line continues the value. All 469 distinct corpus style regions are accepted.
- **Impact**: style bodies cannot be a lenient catch-all, but real corpora never hit the error paths.
- **Confidence**: High

## Observation: a push context cannot reject an unterminated block; join can
- **Context**: modelling a validated multiline body.
- **Finding**: the interpreter accepts a block that ends with a pushed context still open (engine.py `_run`), so `<style>` + push cannot reject a missing `</style>`. Tokens also span lines. A `join` with uncapped max_lines whose parts match the whole block (U+E100 as the newline token) is exact. Smallest-k plus a lookahead that "the first END line is the last line" reproduces CommandMultilines2's first-END completion. A second join that needs one U+E100 and pushes an empty context rejects failed blocks.
- **Impact**: reusable pattern for any multiline body that upstream parses in execute(). Emitters see joins as dead single lines, so give them a separate `single` + `push` entry for structure.
- **Confidence**: High

## Observation: inline lookarounds across Part leaves are impossible; keep guards self-contained
- **Context**: writing the joined-text grammar.
- **Finding**: `part_to_regex` wraps each leaf in `(?i:...)`/`(?-i:...)`, so an atomic group or lookahead cannot span refs. "Not past the last line" guards were written END-free (`(?![^]*)` = last joiner) so that only one leaf carries the END pattern. Maximal munch across structured loops needs explicit `(?!)` / `(?!:)` / `(?!,)` lookaheads; without them backtracking accepted `--x` at end of stream.
- **Impact**: family authors composing multi-leaf grammars must enforce greediness with lookaheads.
- **Confidence**: High

## Observation: an uncapped `join` in `main` is cubic per block without an early exit
- **Context**: T16 found a 45,512-line sequence block timing out once `style` is included.
- **Finding**: `scan_join` joins body[i:j] for every k up to max_lines on every line that reaches the rule, with no first-line check. With max_lines 100000 (upstream CommandMultilines2 is uncapped) that is O(n^2) per line. A partial-match early exit (`fullmatch(joined + U+E100, partial=True)`) restores 0.7 s and changes no verdicts; it is queued in reports/queued-shared-changes.md.
- **Impact**: until the scan fix lands, any model with a large-cap join in a frequently reached context times out on very long blocks.
- **Confidence**: High (mechanism confirmed by patching; verdict equivalence checked on 1071 tests + style corpora)

## Observation: a catch-all line rule inside a pushed context makes Lark Earley slow
- **Context**: T16 measured vega HideShow002_Test.puml Lark parse at 4.6 s -> 21.9 s once `style` was included.
- **Finding**: an isolation over variant grammars showed the cost came only from the `single` `<style>` + `push: style_body` entry, even with style_body reduced to END + `.*`. Lark emits a push as `(line? _NL)* pop_line`, and a catch-all line keeps that derivation alive past `</style>` to the block end. The same entry as `multiline` + `end` + `push` (Lark ignores transitions on multiline; TextMate nests the pushed context's patterns) gives 5.5 s vs 5.1 s without style.
- **Impact**: for emitter-only structure, prefer `multiline` + `end` + `push` over `single` + `push` whenever the context has a catch-all.
- **Confidence**: High (variant grammars timed; mechanism inferred from the emitted rule shape)
