## Observation: files rejects only a style crash that is not a StyleParsingException
- **Context**: deciding what FilesDiagramFactory (non-command) rejects.
- **Finding**: FilesDiagram.java:66-70 catches StyleParsingException from the style parse, so only IllegalStateException / NullPointerException (StyleParser.java:104-113, :121, :129, :153-172, :209) reject, reported at the `@end` line (PSystemBuilder.java:275-281). The parse runs over ALL style blocks as one token stream, and the `</style>` line itself is tokenized (unlike CommandStyleMultilinesCSS). StyleExtractor (jsondiagram/StyleExtractor.java:63-103) counts the `@start` line in `list`, so the header (`!assume `, `hide `, `title `, `skinparam x {` skip loop) ends at the first other non-blank line. `/` entries and `<note>` never fail. A reference implementation in tests/families/test_board_files_git.py agrees with the jar on 2098/2100 random bodies (the other 2 are preprocessor errors from unclosed `/'`).
- **Impact**: style.yaml's grammar (no error at all) cannot be reused for files; board-files-git-files-style.yaml is the crash-only variant.
- **Confidence**: High

## Observation: regex backtracking invents parses Java never makes; guard every deterministic optional
- **Context**: whole-block `join` patterns for the files style stream.
- **Finding**: a skipped optional STAR, a non-maximal skipNewLines or skipColon let the regex reach a StyleParsingException position the parser never reaches (false accepts). Each is now guarded by a lookahead leaf (`(?!GAP\*)` on the no-star branch only: Java takes at most ONE star). Found only by fuzzing against the reference.
- **Impact**: any family writing a parser as a regex should fuzz it against a reference.
- **Confidence**: High

## Observation: an unterminated block can be checked exactly with require_pop plus statement chunks
- **Context**: a `<style>` with no `</style>` runs to the end of the body; the stream end matters (NPE).
- **Finding**: FilesStyleOpen pushes a context with `require_pop` whose only missing entry is `</style>`; if the block ends there, the retry enters `files_unterminated`, where `join` entries consume chunks that end at a line end in statement-start state. A pending end leaves a line no entry takes. Only a value followed by `//` on the very last line stays a false reject (gap fixture).
- **Impact**: reusable "end of block must be in state X" pattern without gives/needs.
- **Confidence**: High (fuzz: 0 single-block mismatches outside the documented gaps)

## Observation: a `set` on every line makes Lark slow; give emitters a flat view
- **Context**: Lark timeouts on pdiff dbhum/n_oj/nojeru-23-tavo641.puml (71 s, 179 lines).
- **Finding**: files lines all `set` the body context; Lark renders that as right-nested blocks, and overlapping alternatives multiply derivations. Marking transition entries `emit: false` and adding transition-free, disjoint "view" entries placed after the interpreter's catch-all (so the interpreter never selects them) brought it to 0.4 s. A git line rule with several nullable leaves cost 15 s on a 2290-line block; one `[^*]*` + `*` + `[ -].*` costs 6 s.
- **Confidence**: High (measured with lark_parse.build_parser)

## Observation: a zero-width leaf is dropped by the Lark emitter (again)
- **Context**: board activity rule `(?!\+)` as its own leaf.
- **Finding**: Lark accepted a leading release because the lookahead vanished (T26 saw the same with `\b`). Folding it into the label leaf fixed it.
- **Confidence**: High

## Observation: shared-tree gates can fail transiently while other families write models
- **Context**: full gate run mid-T31.
- **Finding**: tests/emit/test_linebound_real.py (three whitespace terminals crossing line ends), test_textmate PCRE "regular expression is too large" and two test_description cases failed once and passed on a rerun 20 minutes later; the linebound set was identical with the board-files-git models removed (A/B emit), so it came from other families' untracked in-progress models.
- **Impact**: A/B the failing check with your own models removed before chasing it.
- **Confidence**: High

## Observation: git acceptance is a 2D walk
- **Context**: GitDiagramFactory.
- **Finding**: only "first `*` of a line followed by space or `-`" is line-local (Commit.java:52-53). The ancestor walk (CursorPosition.java:117-213) and the name lookup (GNodeBuilder.java:61-63) read characters in the same column of other lines; gap fixtures pin both.
- **Confidence**: High
