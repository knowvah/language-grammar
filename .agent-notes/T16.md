## Observation: base64 sprites are rewritten to md5 before any command runs
- **Context**: Looking for a positive fixture for CommandSpriteMd5.
- **Finding**: `core/UmlSource.java:332-363` (97a5992) replaces every `data:image/png;base64,XXXX` with `data:image/png;md5,<md5(XXXX)>` and stores the data in an md5 map. So upstream `sprite $x data:image/png;base64,...` is matched by CommandSpriteMd5, and CommandSpriteBase64 is effectively unreachable. tools/interp/source.py does not rewrite, so the interpreter matches Base64. The verdict is the same.
- **Impact**: Do not expect Base64-vs-Md5 command attribution to agree with upstream. A hand-written `md5,<hex>` reference is accepted only if the same block also contains the base64 form.
- **Confidence**: High (source read; fixture `pos/sprite-base64` accepted by the jar)

## Observation: triple-mark folding is disabled; `%newline()` is the only route to CommandSkinParamJaws
- **Context**: Finding an input that reaches CommandSkinParamJaws (`` in the line).
- **Finding**: `jaws/JawsFlags.java:41` `PARSE_NEW_MULTILINE_TRIPLE_MARKS = false`, so `'''`/`!!!`/`"""` blocks are not merged. `%newline()` (or a literal U+E100 in the source) produces the folded line. The jar accepts `skinparam sequence {<U+E100>ArrowColor red<U+E100>}`. Raw-mode interp does not expand `%newline()` (preproc gap).
- **Impact**: Jaws fixtures use a literal U+E100, which works identically in the jar and the interpreter.
- **Confidence**: High

## Observation: narrowing `parts` to model an execute-time error falls through to later commands
- **Context**: Refining `page 0x1`, `scale 0`, sprite levels in common.yaml.
- **Finding**: Upstream matches the line and fails (`PSystemCommandFactory.java:179-187`). A narrowed rule instead lets the line reach later commands. Salt's `CommandAnything` (after the common block) then accepts `page 0x1`. Lines inside the common block were made safe by narrowing CommandSpriteFile too.
- **Impact**: Families with a catch-all command after the common block inherit this gap until an entry-level `reject` exists (queued, reports/queued-shared-changes.md).
- **Confidence**: High (gap/salt-page-zero)

## Observation: the interpreter accepts a block that ends inside a pushed context
- **Context**: Turning skinparam `{ }` and sprite bodies into push contexts to validate body lines.
- **Finding**: `Interpreter._run` ignores the stack at the end of the body. An unterminated `skinparam x {` whose remaining lines happen to be valid body lines is accepted; the jar rejects it, because a multiline command that never completes is skipped. Lark requires the pop line, so Lark is exact there.
- **Impact**: Push contexts trade unterminated-body exactness for body validation; `require_pop` queued.
- **Confidence**: High (5 strict-xfail gap fixtures)

## Observation: gray-16 sprite data is only checked up to the first line's width
- **Context**: Modelling sprite data validity.
- **Finding**: `SpriteGrayLevel.java:190-199` builds width from the first data line and skips columns beyond it, so `FF` then `FF!!` is accepted while `FFFF` then `F!` is rejected. The exact rule is context-sensitive. The model requires the first line all hex and later lines to start with a hex digit (never a false reject). No corpus has non-hex gray-16 data.
- **Confidence**: High

## Observation: npm test only compiles regexes of models that a diagram model includes
- **Context**: Checking Oniguruma for common.yaml.
- **Finding**: The TextMate emitter emits diagram models; a `layer: shared` model nobody includes yet contributes no regexes to `dist/`, so `npm test` passes without checking it. Checked instead by emitting from a scratch model dir with probe diagram models (1,541 regexes, 0 Oniguruma failures) and pcre2 on the 40 common regexes.
- **Impact**: Shared-model tasks need their own emitter check until a diagram includes them.
- **Confidence**: High

## Observation: reject after the narrowed rule keeps emitters exact
- **Context**: Converting execute-time refinements to the `reject` contract (063d6ee).
- **Finding**: The rejects go in `model/diagrams/common-errors.yaml` (`insert_after` each narrowed rule, with the generated shape). This equals "reject before the unnarrowed rule" for the interpreter. Emitters drop `reject` entries, so they keep the narrowed rule, and Lark/TextMate still refuse `scale 0`. With the reject-before variant the emitters would get the unnarrowed regex. The CommandSpriteFile narrowing became unnecessary and was removed.
- **Impact**: Families converting execute-time errors should prefer narrowed rule + `insert_after` reject.
- **Confidence**: High
