## Observation: a gantt with only separators or groups crashes in checkFinalError
- **Context**: T13's known FA (`-- Phase one --` alone accepted by gen-gantt-diagram, rejected by the jar).
- **Finding**: separators and groups enter the task map, but `TimeBoundsData.initMinMax` skips them (gantt/data/TimeBoundsData.java:131-142). With no real task `maxDay` stays null, `durationInDays` (:155) throws `NullPointerException: temporal`, `GanttDiagram.checkFinalError` (:172-181) catches only ImpossibleSolvingException, and PSystemBuilder.java:275-280 reports the crash at the `@end` line. A real task before or after the separator, or inside the group, avoids it. A colored day does not.
- **Impact**: a context stack cannot express this, because a pop restores the frame below, which was fixed at push time. The gap fixtures are `tests/fixtures/gantt/gap/*-only.puml`. An order-free `gives`/`needs` flag proposal is queued in reports/queued-shared-changes.md.
- **Confidence**: High (oracle and `-syntax` probes)

## Observation: a push from a stateful bottom context loses the state on pop; use a flat depth-1 context
- **Context**: gantt needs two pieces of state, "a task-like entry exists" (for `note bottom`, `A -> B` and `[A] #c` in `main`) and group depth (`end group`).
- **Finding**: the first group opened from `main` would `push` and then pop back to `main`, losing "a task exists". The model `set`s a flat `gantt_group_1` (state "tasks, depth 1"). Its `end group` `set`s `gantt_tasks`, and deeper groups push `gantt_group` from any task state. Group start and end are removed from the generated list and become per-context heads that cite GanttDiagram, so the remove keys spare them.
- **Impact**: reusable whenever a nesting construct also flips a monotone diagram flag.
- **Confidence**: High (fixtures pos/groups*, neg/end-group-*)

## Observation: UBrex `〴d` is [0-9_], so `_` passes date shapes and then fails parseInt
- **Context**: `print between` dates and counts.
- **Finding**: com/plantuml/ubrex/CharClassRaw.java:65-69 defines DIGIT as `0-9` or `_`. `D+_` and `2020-01-1_` fit the shape and then fail with a NumberFormatException, which is an execution error. LocalDate.of applies ISO calendar validity: Feb 29 needs a leap year, year 0 and 400 are leap, 100 and 1900 are not. `model/diagrams/gantt-dates.yaml` `GD_DATE_ANY_OK` is the exact subset of the shape that executes. T25 can reuse it for every sentence date.
- **Confidence**: High (oracle probes, test_numeric_dates_agree_with_local_date)

## Observation: Lark cannot reach 10-digit JAVA_INT values in the middle of a line
- **Context**: Lark run over the gantt fixtures (`print between D+2147483647 and ...`).
- **Finding**: common's JAVA_INT_RANGE lists `[1-9][0-9]{0,8}` first. Lark's single `regex.match` per terminal then yields 9 digits and only ever shortens that match. At a line end the tail lookahead hides the problem. `page 2147483647x1` is a Lark false reject too. Listing the longest alternatives first fixes it (verified in a scratch build). Queued for common.
- **Impact**: any hand-written alternation of digit ranges should list its longest alternatives first.
- **Confidence**: High

## Observation: smaller gantt execute errors (oracle-verified)
- **Finding**: a bare `footbox` is an NPE: TYPE is optional in CommandFootbox.HIDE_SHOW_FOOTBOX, and CommandFootboxGantt.java:56 calls equalsIgnoreCase on it. An empty `note bottom` body fails with "No note defined". A blank body line counts as content, but a `'` comment line is removed by preprocessing, so a note with only a comment is empty. A 1-character hex color (`#a`) is valid and 2 characters are not. `language é` matches nothing because `\w` is ASCII in Java. `oracle_verdicts` keys its result by `str(path)`.
- **Confidence**: High
