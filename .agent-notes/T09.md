## Observation: Dynamic Earley rejects zero-width regex terminals
- **Context**: Emitting Lark terminals from model regexes (T09).
- **Finding**: `Lark(lexer="dynamic")` raises GrammarError for any terminal whose static min
  width is 0 (e.g. `\s*`). Lark computes width with `sre_parse`; on syntax it rejects
  (`(?V0)`) it falls back to `regex.match('')`. Emitting nullable regexes as
  `(/(?V0)(?=[\s\S])(?:P)/)?` passes; runtime zero-width matches are silently dropped.
- **Impact**: Do not "simplify" the guard in tools/emit/lark.py.
- **Confidence**: High

## Observation: `regex=True` needed for `\p{L}` in Lark
- **Context**: Parser construction in tools/validate/lark_parse.py.
- **Finding**: Lark(regex=True) uses the `regex` module; lark's width check substitutes `\p{..}`.
- **Impact**: Keep `regex=True` wherever the .lark is loaded.
- **Confidence**: High
