## Observation: a gantt sentence ignores everything after its last phrase
- **Context**: modeling NaturalGanttCommand (gantt/command/NaturalGanttCommand.java:74-144).
- **Finding**: isValid only needs the subject and one verb phrase prefix (VerbPhraseAction.check matches nothing to the end of the line). execute returns OK as soon as ` and ` (spaces, `and`, spaces) does not follow a phrase, so `[A] lasts 5 days garbage`, `[A] starts D+5 10:00` and `[A] lasts 2 days and` are accepted. After ` and `, some phrase must check, otherwise the command fails with "No matching verb phrase". The command owns the line once isValid passes, so every execution failure rejects the line.
- **Impact**: per subject the model has an Invalid reject, the accept entry, and an Unmatched reject with the isValid shape. The accept's tail refuses a word continuation followed by ` and `, which emulates UBrex's committed match. Cost: one FR gap (`5 daysxyz and foo`, sentences/gap/glued-word-and).
- **Confidence**: High (oracle probes)

## Observation: validated date regexes exceed PCRE2's size limit inside a sentence
- **Context**: emitting the task sentence (24 phrases) to TextMate.
- **Finding**: PCRE2 compiles at most about 4 copies of the validated date (gantt-dates GD_DATE_ANY_OK), against 24+ of the generated date shape. Form A, with its month lookaheads, costs 1/21 of the budget. Accept entries therefore use the gantt-lang shapes, written as `plus(PHRASE (AND | TAIL))` so that each phrase set appears once (task sentence 15.7k characters, compiles). Validity lives in interpreter-only rejects with positive invalid-field grammars (gantt-sentences-bad), so nothing needs flattening into a lookahead.
- **Impact**: emitters accept invalid sentence dates and numbers. This is a documented superset.
- **Confidence**: High (measured with the pcre2 binding)

## Observation: `{R} works on [T]` can never succeed
- **Context**: a positive fixture was rejected by the jar.
- **Finding**: ComplementTask names the whole bracketed code COMPLEMENT and looks up `[A]` with its brackets (gantt/lang/ComplementTask.java:49-58). No task code can contain `[`, so the line always fails with "No such task [A]". It is modeled as an always-invalid resource phrase.
- **Confidence**: High (jar, with task A declared)

## Observation: sentence state errors and what stays open
- **Finding**:
  - `it` needs an earlier task-subject sentence (SubjectTask.java:444-460); arrows do not set it.
  - `they`/`he`/`she` need an earlier `{R}` subject (SubjectResource.java:68-76).
  - `project starts` fails once any task, separator or group exists (GanttDiagram.java:340-346).
  - Absolute `starts`/`ends` fail with "No starting date for the project" without an earlier `project starts` (SubjectTask.java:105-107, :172-173, :262-263, :305-306). Relative dates are fine.
  - Invalid working hours parse to null and crash only once a task exists, before or after.
  - The 20-year span is measured from 1970-01-01 when there is no `project starts`, so any dated colored day or task after 1989 fails at the end.
- **Impact**: modeled: `it` in `main`, `project starts` in the task states (heads on the T24 anchors), and, after the diagram-flag contract (5834289), "No starting date" (`needs: project_start` on the interpreter-only NaturalGanttTaskNeedsStart and its main head, `gives` on `project starts`) and the separator/group final check (`needs`/`gives: real_task`). The rest are gap fixtures.
- **Confidence**: High (oracle probes)

## Observation: upstream sentence quirks the generated shapes already mirror
- **Finding**: `before the`/`after the` (IGNORED_5/6) and `to the` (Words.uexactly + uzeroOrMore(THE)) need `the` glued to the previous word, so `{R} is off after the 2023-12-04` is a syntax error in the jar (pdiff govacu). `{R} starts ...` is not a sentence. ## Observation: an absolute date shape also fits non-date phrases
- **Context**: the first needs-start entry rejected pdiff batopu/furaxa (`[task2] starts 20 days after [task1]'s end and lasts 3 days`).
- **Finding**: date shape B takes any non-digit run as its separators, so the line reads as the date 20/1/3. Upstream checks the before/after-task phrase (and the relative phrase) before the date phrase, so it commits to "after [task1]'s end". A phrase that must be the committed one therefore needs a negative lookahead for every earlier phrase of the same verb. The lookahead must also tolerate leading spaces: `GS_SP` is optional, so a regex can otherwise place the lookahead before the spaces and let a later optional `GS_SP` consume them.
- **Impact**: GS_NOT_BEFORE_OR_RELATIVE is a flat copy of the two check shapes, pinned by a test. The same rule applies to any flag or state attached to one specific phrase.
- **Confidence**: High (pdiff FR reproduced and fixed)
