## Observation: salt widgets are parsed only when drawing; the syntax check never sees them
- **Context**: deciding what of salt's structure the jar rejects.
- **Finding**: PSystemSaltFactory is the common block plus CommandAnything `(.*)` (doTrim=false), which only stores the line (salt/CommandAnything.java:72). DataSourceImpl and every Element*Factory run in PSystemSalt.getTextBlock -> createElement (salt/PSystemSalt.java:111-132, :174-235). The jar accepts unbalanced/stray braces, unknown tokens, a bad border position, an unclosed `<<image`, an unknown `<<name>>` and a lone `"` (they fail only at render time).
- **Impact**: salt structure is highlighting-only; model/diagrams/salt.yaml refines CommandAnything's parts into a tokenizer-shaped row that matches exactly the lines `^(.*)$` matches.
- **Confidence**: High (111 oracle probes; tests/fixtures/salt/pos/render-*)

## Observation: the only salt-specific reject is a first data line `salt`, and data can stay empty
- **Context**: CommandAnything.executeArg.
- **Finding**: `diagram.size() == 0 && s.trim().equals("salt")` fails (CommandAnything.java:69-71). Common commands and blank lines do not add data; `scale abc` or `hide stereotype` do (CommandAnything takes them). `PSystemSalt.add` stores `s.split(U+E100)` (StringLocated.java:141-143); Java's split drops trailing empty strings, so a line made only of U+E100 adds nothing and a following `salt` is still rejected, while ` <U+E100>` adds data.
- **Impact**: modeled as a `main` "no data" state (head reject + an untrimmed `+` head entry) and CommandAnything `set: salt_data`.
- **Confidence**: High (oracle-verified)

## Observation: an inconsistent bracket body line falls through to the next command
- **Context**: `skinparam foo {` / `[OK]` / `}` accepted by the jar, rejected once salt included `common`.
- **Finding**: CommandMultilinesBracket.isValid returns NOT_OK at the first line SkinLoader.p1 rejects (CommandMultilinesBracket.java:76-79), and getCandidate `continue`s with the next command for the START line (PSystemCommandFactory.java:236-240), not only when the block ends. common's `skinparam_body` fails that line instead. Same verdict for every factory where no later command takes `skinparam x {`; salt's catch-all does. salt.yaml inserts an `emit: false` catch-all after CommandSkinParamBodySetting that `set`s a never-popping context, so the block end backtracks the `require_pop` push (a `set` keeps the frame's resume point, engine `_track`).
- **Impact**: any future family with a catch-all after the common block needs the same insert (or common could adopt it if the contract gains "backtrack on body failure").
- **Confidence**: High (oracle probes sp-*, fixtures pos/skinparam-abandoned*)

## Observation: Java `.` refuses U+0085/U+2028/U+2029; generated `.` accepts them
- **Context**: probing control and separator characters in salt lines.
- **Finding**: Pattern2 compiles without DOTALL/UNIX_LINES (regex/Pattern2.java:114), commands match with find() (regex/RegexComposed.java:112-118), so `^(.*)$` accepts such a character only as the last one (`$` before a final terminator). `a<U+2028>b` fails every salt command; `ab<U+2028>`, a lone `<U+2028>` and VT/FF/NUL are accepted. The translator copies `.`, and Python's `.` matches them.
- **Impact**: generated `.` slots accept these lines in every family (gap/title-line-separator); translator fix queued in reports/queued-shared-changes.md. Hand-written Parts should not rely on `.` for Java exactness.
- **Confidence**: High (oracle-verified)

## Observation: `@startuml` + `salt` needs no model
- **Context**: "salt inside @startuml".
- **Finding**: `@startuml` never reaches PSystemSaltFactory (core/DiagramType.java:197-200). A second line that trims to `salt` is an EXECUTION_ERROR before any factory runs (error/PSystemErrorUtils.java:81-87, PSystemBuilder.java:252-255); the interpreter has no such pre-check but every `uml` factory rejects a bare `salt` line, so verdicts agree (11 probes; `salt<NBSP>` is DESCRIPTION in both). `{{salt` ... `}}` (EmbeddedDiagram.java:337-338) is drawn only at render time; single-line commands get only the `{{` line (getCandidate, PSystemCommandFactory.java:224), grouping happens in multiline scans (:288-307).
- **Confidence**: High (oracle-verified)
