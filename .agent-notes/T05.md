## Observation: SyntaxChecker.checkSyntax is not a per-block verdict
- **Context**: Building the T05 oracle (stock jar 97a5992).
- **Finding**: `checkSyntax(String)` rejects any string not starting with
  `@startuml\n` or not ending with `@enduml` (SyntaxChecker.java:67,73) and only checks
  `blocks.get(0)` (:89). So `@startpacket`/`@startgantt`/etc. files and files with
  trailing text after `@enduml` read as errors at line 1/last line. `checkSyntaxFair`
  (:107) has no gates; Oracle.java mirrors its classification per block over
  `SourceStringReader.getBlocks()`, which is also what the CLI does.
- **Impact**: Do not use `checkSyntax` for verdicts. Vega: 97 of 301 files differ
  between `checkSyntax` and the oracle, all due to those gates.
- **Confidence**: High

## Observation: PSystemError line location is 0-based
- **Context**: Reporting `error_line`.
- **Finding**: `LineLocation.getPosition()` starts at 0; Oracle emits position+1. Vega YAML
  header lines are blanked (not removed) before checking so numbers match the file.
  For a block with an unterminated `class Foo {`, the error line is the `class` line
  (2), not the garbage line.
- **Impact**: error_line is the first line of the failing construct as upstream reports.
- **Confidence**: High
