## Observation: a participant-less sequence diagram is not an error but "not mine"
- **Context**: probing minimal bodies (`autonumber`, `== x ==`, `title x`) against the jar.
- **Finding**: `PSystemCommandFactory.finalizeDiagram` returns `null` when `sys.isIncomplete()` (`command/PSystemCommandFactory.java:161-162`); `SequenceDiagram.isIncomplete` is `participantsList.size() == 0` (`sequencediagram/SequenceDiagram.java:591-593`). The jar then tries the next factory: `title x` alone is CLASS, `== x ==` alone is rejected by all. `hide unlinked` removes unlinked participants first (`:597-598`), so `participant A` + `hide unlinked` is incomplete too. No line model can count "at least one participant" (a `require_pop` frame can only be closed by a pop back to the context below it, which was fixed at push time).
- **Impact**: the interpreter attributes participant-less bodies to SEQUENCE (diagram mismatch, rare FA); pinned by gap fixtures `no-participant`, `hide-unlinked-removes-all`. A model-level "require one of these rules" key would close it.
- **Confidence**: High (oracle-verified)

## Observation: CommandArrow is skipped for trimmed lines over 2000 characters
- **Context**: a new interpreter timeout on plantuml-ts `class/borala-01-tepu803.puml` (one 65,838-dash line `p ---...--->`).
- **Finding**: `CommandArrow.getRegexConcat()` ends in `.protectSize(2000)` (`sequencediagram/command/CommandArrow.java:133`); `RegexConcat.match` returns false for longer lines (`regex/RegexConcat.java:127-130`). The extractor does not carry `limitSize`, so `gen-sequence-diagram` CommandArrow matches long lines upstream never matches. Failing the arrow regex is O(n^2) in a dash run (`(-+)STYLE(-*)`): 9 s for the generated rule at n=65,838. `sequence-errors` adds a `(?![\s\S]{2001})` guard (0.000 s); the jar confirms a 2100-char message line is rejected and a 2100-dash exo arrow accepted. It is the only `protectSize` call at the pin.
- **Impact**: the extractor/translator could emit the guard for every `protectSize` command; Lark drops zero-width terminals, so emitters do not enforce it.
- **Confidence**: High

## Observation: including `common` roughly doubles Lark parse time of long sequence blocks
- **Context**: vega `asciiverse/timeline_002.puml` (70 lines) timed out under `--lark all` (10 s budget).
- **Finding**: 4.8 s with the pre-T17 grammar (gen-sequence-diagram alone), 10.8-11.8 s with a probe `include: [gen-sequence-diagram, common]` and no T17 change, 11.2-11.9 s with `sequence`. Same with the group lines removed, so group nesting is not the cost. Writing the arrow with structured shared variables (COLOR_REF, URL_LINK, ...) instead of the generated flat regexes did not change it measurably.
- **Impact**: every family that includes `common` will see more Lark timeouts at 10 s; T16 recorded the same for class. `--timeout 30` gives 0 disagreements on the vega sequence slice.
- **Confidence**: High (measured)

## Observation: per-context behaviour of one generated entry needs tail entries
- **Context**: rejecting `end`/`else`/`end box` only when no group/box is open.
- **Finding**: patches (`overrides`, `insert_*`) apply to every splice of an entry alike, and a class-name key also hits hand-written entries citing that class. So a closer cannot reject in `main` and pop in `group_body` through the generated entry. Working pattern: narrow CommandGrouping to start types, remove CommandBoxEnd, put the closers at the TAIL of each context (`main`, `group_body`, `box_body` each = `include: gen-sequence-diagram#main` + tail), and narrow the one later command that could steal a closer-shaped line (CommandActivate2 `end ++`). Tail entries cite `SequenceDiagram` so the `CommandBoxEnd` remove key does not delete them; coverage then needs an exclusion for CommandBoxEnd.
- **Impact**: reusable for any family whose closers depend on an open construct (activity `end`, state `}`).
- **Confidence**: High

## Observation: unknown colors are execution errors in many sequence slots
- **Context**: neg/gap fixtures.
- **Finding**: `HColorSet.getColor` throws NoSuchColorException (`klimt/color/HColorSet.java:69-73`), so `A -> B #zzzz`, `activate A #zzzz`, `alt#zzzz`, `return #zzzz x`, `-[#zzzz]>` and a participant `#back:..;line:..` spec are rejected. Narrowing each slot needs a full copy of each command's parts (no leaf-level override).
- **Impact**: left as gap fixtures; a shared COLOR_VALID plus a leaf-level patch key would serve every family.
- **Confidence**: High (oracle-verified)
