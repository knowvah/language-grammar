## Observation: preproc keywords are classified case-insensitively but read case-sensitively
- **Context**: Choosing `ci` for model/preproc.yaml.
- **Finding**: `TLineType` classifies lines with IRegex/Pattern2, which is CASE_INSENSITIVE (`text/TLineType.java:151-260`, `regex/Pattern2.java:114`). Eaters then re-read the keyword with case-sensitive `checkAndEatChar` (`tim/Eater.java:252-279`). So `!IF 1`, `!LOG x` and `!INCLUDEDEF x` are errors, not plain lines. Closers that no Eater re-reads (`!else`, `!endif`, `!endwhile`, `!endfor`, `!endsub`, `!end function|definelong|procedure`) are effectively case-insensitive: the jar accepts `!ELSE`, `!ENDIF` and `!End Procedure`. `!exit` is exact and case-sensitive (`utils/StartUtils.java:131-150`). `%function` names are case-sensitive: `%UPPER(x)` stays text.
- **Impact**: model/preproc.yaml uses `ci: true` only on the closers. tests/layers/test_preproc.py pins this split.
- **Confidence**: High (oracle-verified)

## Observation: surprising preprocessor verdicts at 97a5992
- **Context**: Probing directive edge cases against the stock jar.
- **Finding**:
  - A stray `!endfunction` or `!endprocedure` at top level is accepted. `TContext.java:440-442` builds `CommandExecutionResult.error` and discards it.
  - An unclosed `!if` is accepted. A missing `!endprocedure`, `!enddefinelong`, `!endfunction` or `!endsub` is rejected.
  - Top-level `!local $x = 1` is rejected, but `!global` is accepted.
  - `!includedef` with a missing file, or no argument at all, is accepted.
  - `!elseif` is only parsed when no earlier branch was taken. `!if 1` then a bare `!elseif` is accepted.
  - The if, while, foreach and sub stacks are independent. `!if 1` / `!while 0` / `!endif` / `!endwhile` is accepted.
  - `!exit` truncates the block before TIM runs (`BlockUmlBuilder.java:109-113`), even inside a procedure body.
  - A function body without `!return` is rejected when it is declared.
- **Impact**: These shape the model's contexts. The last three bullets are documented gaps in the model header.
- **Confidence**: High (oracle-verified)

## Observation: oracle include/import paths resolve against the JVM cwd
- **Context**: Picking a positive `!import` fixture.
- **Finding**: tools/oracle/Oracle.java reads files through `SourceStringReader`, so relative `!import`/`!include` paths resolve against the Python process's cwd. vega `sub/includesub-basic-with-include.puml` is rejected for this reason. The fixtures use `/etc/hosts` and stdlib `<C4/C4>` instead.
- **Impact**: Parity will see spurious rejects on corpus files that include relative paths. T12/T16 should count these as an oracle-setup effect, not as model disagreements.
- **Confidence**: High

## Observation: raw-mode agreement with the preproc model (informational, T12/T16)
- **Context**: `accepts(models, raw_block, raw=True)` vs `oracle_verdicts` per block, with blocks from `split_blocks`.
- **Finding**:

  | Corpus (blocks) | Agree / disagree with preproc model | Without it (baseline) |
  |---|---|---|
  | vega (301) | 280 / 21 | 270 / 31 |
  | plantuml-ts (4401) | 4155 / 246 | 3965 / 436 |

  - **vega**: 18 of the 21 remaining blocks contain no `!` line: 14 are gantt family gaps, 4 are crash/packet false accepts. The other 3 are an unexpanded unquoted call (`box("single line")`), a relative `!includesub` the oracle cannot resolve, and gantt6, which now fails on a gantt line.
  - **plantuml-ts**: the top cause is unexpanded call lines `name(...)` (133). Then come 47 non-`!` false accepts, 24 diagram lines in `!` blocks, 21 non-`!` diagram gaps, and 14 runtime-fact false accepts (`!assert` false, `!final` redefinition, procedure results).
  - **Call-site alternatives measured on plantuml-ts, not adopted**: a rule consuming `$name(...)` lines gives 4177 agree; one consuming any `name(...)` line gives 4217. Non-`!` blocks are unchanged in both.
  - **Why not adopted**: upstream expands only declared names, and the generic rule would also claim class members like `foo()`.
- **Impact**: Raw mode is secondary to the L2 run. The remaining preproc-related disagreements are mostly unexpanded call sites, plus runtime facts: asserts, `!final` redefinitions and missing files.
- **Confidence**: High (measured)
