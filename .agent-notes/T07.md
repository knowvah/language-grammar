## Observation: UBrex is non-backtracking; UBrexCommandIf accepts `if x then`
- **Context**: translating ub-* trees (ubrex_regex.py) and checking the T07 acceptance criterion.
- **Finding**: every Challenge returns one match length and the parent continues from it
  (`CompositeList.java:100`); alternatives are first-match, quantifiers greedy with no give-back. Plain regex
  parts are therefore a superset; commands containing alt/opt/star/plus carry warning
  `semantics:committed-match` (13 commands). Bounded repetition, UpTo and Lazy/OldVersion are emitted with
  lookaheads so they are exact. `UBrexCommandIf.java:85-87` alternative 4 (`if` s+ IF2=`.+`) accepts a bare
  `if x then`, so the "rejects `if x then`" criterion holds only at diagram level (oracle rejects it inside a
  `start ... stop` block because the new-syntax factory has no matching command), not for the regex itself.
- **Impact**: do not expect the UBrexCommandIf regex to reject `if x then`; use `if`, `iff (x) then` instead.
- **Confidence**: High (oracle + interpreter agree on 6 of 7 probes; the 7th is below).

## Observation: CharSet is ASCII-only by construction
- **Finding**: `CharSet.addChar/addRange` throw outside 32..128 (`CharSet.java:48`), so T03's probe of 32..128 is
  exact. Quirk not modelled: control chars < 32 index bit `c+64` via negative shift (`CharSet.java:106-112`).
  UBrex folds ASCII A-Z only; regex `ci` folds Unicode (U+212A vs k).
- **Confidence**: High
