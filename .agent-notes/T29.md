## Observation: the jar accepts any JSON text in @startjson
- **Context**: Deciding whether the JSON body needs an exact join grammar (like class-diagram `json X {` blocks).
- **Finding**: Every JsonParser error is a ParseException, and JsonDiagramFactory.java:94-96 catches it. The diagram then renders "Your data does not sound like JSON data" (JsonDiagram.java:116-122). Oracle-verified as accepted: garbage, trailing commas, unquoted keys, single quotes, trailing text, `/* */`, and 5000-deep nesting. The jar only rejects on other exceptions, all reported at the @end line:
  - an unclosed header `<style>` or `skinparam ... {` (NoSuchElementException, :79);
  - a malformed `#highlight ` line (Highlighted.java:69-71);
  - StyleParser IllegalStateException or NPE. StyleParsingException is caught at :99-104.
- **Impact**: JSON validity never decides acceptance. The class family's CO_JSON_* grammar does not fit either: it reads lines concatenated with nothing between them, while JSON diagrams join lines with "\n", so `//` comments work there.
- **Confidence**: High

## Observation: `needs` on a never-given flag reproduces whole-diagram failures at the @end line
- **Context**: Non-command factories fail in createSystem, and PSystemBuilder reports the error at the block's last line.
- **Finding**: An entry with `needs: json_throws`, a flag no entry gives, fails the attempt at the @end line. This is the jar's line exactly, and it needs no new contract key. Use `emit: false` on such entries so emitters drop them like `reject`.
- **Impact**: Reusable for other PSystemAbstractFactory families (yaml/hcl if they are ever modeled, misc charts).
- **Confidence**: High (44 fixtures, failure line asserted)

## Observation: Lark `multiline` + `end` bodies run past their first end line
- **Context**: pdiff dbhum/b_it/bitepo-72-vija933.puml (`!theme aws-orange`, 430 lines) timed out in Lark at 25 s.
- **Finding**: Two causes, isolated with variant grammars:
  - A catch-all first data line let every header line act as the `set` spine (25 s down to 3 s when it excludes the header keywords).
  - A multiline `skinparam ... {` structure could end at any later `}`, including the `}` lines inside the theme's `<style>` region (13.6 s down to 5 s under load average 260, with single + push into a context whose body line excludes a lone `}`).
  - Ruled out: the `}` line acting as the spine (excluding it changed nothing).
- **Impact**: For emitter structure, prefer single + push with a body-line rule that cannot match the pop line, over multiline + end, when the end token (`}`) also occurs in later regions.
- **Confidence**: High (variant grammars timed)

## Observation: style.yaml's variables assume the last joined line is the END line
- **Context**: Reusing STYLE_STATEMENT for a join that stopped at the error line plus one.
- **Finding**: STYLE_STRING never matches on the last joined line, and STYLE_VALUE_END accepts "the rest is the last line". A join cut before `</style>` therefore accepted wrong statement splits (fuzz case `jsonDiagram jsonDiagram // c ;` / `, { b`). Anchoring the join so its last line is the first `</style>` fixed it. After that, 1,800 random regions showed no disagreement outside the documented gaps.
- **Impact**: Anyone reusing `style` variables in a join must end the join on the END line.
- **Confidence**: High

## Observation: StyleParser NPEs come from an early end of the token stream
- **Context**: Fuzzing JSON style regions against the jar.
- **Finding**: An unclosed `/*` or `/'`, an unclosed quote, or an `@` token with no `{};` swallows `</style>` and the final newline. The last real token then dereferences a missing next token: :104 (any token), :107 (after readWithComma), :116/:121 (STRING [STAR] and newlines), :129 (STRING and colons, not `--` keys), :153-161 (`:` STRING), :209 (value COLON). A `//` comment instead stops at the newline, so `</style>` stays the next STRING. Fuzz cases with `/'` that fail in the preprocessor ("COMMENT_SIMPLE", truncated preproc lines) are not style errors.
- **Confidence**: High (jar -syntax messages)

## Observation: joins glue `{{ ... }}` units even for non-command factories
- **Context**: Fuzz disagreement with a `{{` line inside a JSON style region.
- **Finding**: tools/interp/scan.py `unit_end` makes the join unable to stop at `</style>`, so the interpreter accepts a region the jar rejects (FA). Single-line rules are not affected. Queued in reports/queued-shared-changes.md.
- **Confidence**: High
