## Observation: ebnf and regex bodies are parsed at execute time, not when drawing
- **Context**: deciding what of `@startebnf` / `@startregex` the jar rejects (unlike salt widgets, T28).
- **Finding**: PSystemEbnf.addBlocLines (ebnf/PSystemEbnf.java:74-83) runs the EbnfExpression tokenizer and returns "Unparsable expression" when a char it does not know clears the tokens (:122-124); an unclosed string throws in CharInspectorImpl.jump (:68-69). PSystemRegex.addBlocLines (regexdiagram/PSystemRegex.java:131-178) lexes, runs a shunting-yard and evaluates on an operand stack. ProtectedCommand (command/ProtectedCommand.java:54-77) turns any Throwable into an execution error, so every parse failure rejects the block.
- **Impact**: both bodies are modeled exactly (ports of the Java code in tests/families/test_meta_diagrams_{ebnf,regex}.py, checked against the jar on random samples).
- **Confidence**: High (1412 EBNF and 600 regex random blocks: port = jar, model = port)

## Observation: the regex diagram's operand stack is shared by all lines
- **Context**: `*` alone rejected, `a` then `*` accepted.
- **Finding**: `stack` is a field of PSystemRegex (:103). A line with h missing operands (quantifier at a start position, `a|`, `(?=)`, `a()`, `(?i)x`) needs h tiles from earlier lines and leaves D + 1 - h, so once D >= 1 it never returns to 0. Common commands (`title`) do not touch it. The depth is unbounded, so a context stack can only track D = 0 vs D >= 1; lines with two or more holes after one tile (`a` / `|`) are an FA gap.
- **Impact**: model/diagrams/meta-diagrams-regex.yaml uses two states and recursive (`(?(DEFINE)...)`) interpreter-only leaves.
- **Confidence**: High

## Observation: PSystemBasicFactory's empty check runs after removeInitialNoise
- **Context**: `@startcreole` / blank line rejected, but blank + `  ` accepted.
- **Finding**: core/UmlSource.java:79-106 drops leading body lines that are exactly "" or start with `skinparam `, `skinparamlocked `, `!pragma ` (case-sensitive, untrimmed); the "2 lines" error (command/PSystemBasicFactory.java:88-90) applies afterwards, unless the source starts with `@startdef` (case-sensitive, UmlSource.java:288-290). So a creole body is accepted iff one line is neither "" nor such a noise line, a whitespace-only line included; `\startdef` / `@startDef` with an empty body are rejected.
- **Impact**: creole models it with `gives`/`needs` flags; def keeps a gap (the start line is not visible to rules). Every other PSystemBasicFactory (math, latex, ditaa, ...) has the same noise rule.
- **Confidence**: High (oracle-verified)

## Observation: generated `$` inside a lookahead breaks Lark; one generated regex has it
- **Context**: Lark rejected a lone `(* comment *)` EBNF line (pdiff jufupa-29-cuge382).
- **Finding**: the translation of UBrexCommandComment ends its COMMENT lookahead with `$` (UBrex end of text). In a Lark terminal `$` means end of input, so the rule never matches mid-file. It is the only such regex in model/generated (grep `\$)`); meta-diagrams-ebnf overrides it with an equivalent `$`-free form.
- **Impact**: translator output with `$` inside a group is unsafe for Lark.
- **Confidence**: High

## Observation: TextMate body lines of command factories get no scopes (CommandNope)
- **Context**: checking EBNF highlighting with vscode-textmate.
- **Finding**: common's CommandNope `[\s\xa0]*` is emitted as a `match` that matches the empty string at column 0 and wins, so whole lines stay `source.plantuml` (class bodies too). Removing it restores scopes. Also: scopes inside a `star` only capture the last iteration. Queued.
- **Confidence**: High

## Observation: Lark document framing differs from upstream for `@startsprites` and `@end<other>`
- **Finding**: tools/emit/lark.py maps each diagram type to one start keyword, so SPRITES (also `@startsprites`) only lands in `block_uml`; and `END_<kw>` requires `@end<kw>` while upstream closes at any `@end...` (StartUtils.java:119-121). Both queued.
- **Confidence**: High

## Observation: tools/emit/linebound.py bounds negated classes, not positive classes that contain `\n`/`\r`
- **Context**: tests/emit/test_linebound_real.py failed on the EBNF whitespace run `[\t-\r...]+` and the regex prefix `[\t\n\x0b\f\r\xa0]*`.
- **Finding**: hand-written positive classes that include `\n`/`\r` (here via a `\t-\r` range for Character.isWhitespace / Java `\s`) produce Lark terminals that cross a line end. Lines never contain `\n`/`\r`, so dropping them from emitted classes is exact.
- **Impact**: write Java-whitespace classes as `[ \t\x0b\f...]` in emitted parts; interpreter-only leaves may keep the full range.
- **Confidence**: High
