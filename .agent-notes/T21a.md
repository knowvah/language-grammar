## Observation: activity3 has no final check; closers follow one strict stack
- **Context**: Deciding whether nesting needs `require_pop`.
- **Finding**: ActivityDiagram3 overrides neither checkFinalError nor isIncomplete (defaults at core/AbstractDiagram.java:162-171). The jar accepts a block that ends inside any if/switch/while/repeat/fork/split body. Every closer checks `current() instanceof X` on ONE instruction stack and errors otherwise (ActivityDiagram3.java:225-435). So mismatched closers (`while`/`endif`), `elseif`/`else` after `else` (InstructionIf.java:166-187), `case` in an `if` inside a switch, `fork again` in a split, and `backward` outside repeat/while are all rejected. Groups and partitions (T21b) share the same stack.
- **Impact**: Model with head `reject` entries per context, not `require_pop`. Any family whose closers are checked against a single stack can reuse the pattern.
- **Confidence**: High (oracle probes; fixtures neg/mismatch-*, pos/unclosed-*)

## Observation: CommandKill3's regex is `^kill|detach;?$` (alternation not grouped)
- **Context**: A neg fixture `kill x` was accepted by the jar.
- **Finding**: `new RegexLeaf("kill|detach")` is not grouped (CommandKill3.java:55-60), and RegexComposed.match uses find() (regex/RegexComposed.java:112-118). The command takes every line starting with `kill` and every line ending with `detach`/`detach;`. The generated model groups the alternation. It is the only ungrouped top-level `|` in a RegexLeaf at the pin (`of|for` in CommandUrl sits inside RegexOptional, which groups it).
- **Impact**: Fixed by an override in activity3-core-actions.yaml. The translator could keep leaf precedence to make this exact for free.
- **Confidence**: High (jar probes: `killer`, `KILL now`, `foo detach` accepted; `skill`, `detach x` rejected)

## Observation: Lark/W3C emit `set` as `push`
- **Context**: Lark sample after modeling `else` as `set: a3_if_else` and `case` as `set: a3_switch_case`.
- **Finding**: `set` targets nest inside the current block (tools/emit/lark.py:30-33), so every if/else needs two `endif` lines in Lark (11 disagreements and 2 timeouts in a 100-block sample, against 3 and 2 in the baseline). With a scratch emitter where `set` inside a pushed context ends the block like `pop` and continues into the target, the count drops to 3 disagreements and 1 timeout. Queued (reports/queued-shared-changes.md). The Lark multiline `end` part also lacks `_WS?`, so indented `end note` never matches. That is pre-existing; also queued and verified.
- **Impact**: Until the queued fix lands, Lark disagrees on activity3 if/else and switch blocks.
- **Confidence**: High

## Observation: SDL shape terminators no longer exist at the pin
- **Context**: Spec scope "SDL shape terminators (`|`, `<`, `>`, `/`, `\\`, `]`, `}`)".
- **Finding**: CommandActivity3 (CommandActivity3.java:66-77) ends an action only with `;`; box shapes are stereotypes after it (`:a; <<input>>`, `<<output>>`, `<<procedure>>`, `<<load>>`, `<<save>>`, `<<continuous>>`, `<<task>>`). The jar rejects `:a|`, `:a<`, `:a>`, `:a/`, `:a]`, `:a}`. `:a\` is also rejected (the trailing backslash joins the `@enduml` line).
- **Impact**: Modeled as rejected (neg/activity-sdl-*); stereotype forms in pos/activity-stereotypes.
- **Confidence**: High

## Observation: a head reject shape must not be broader than what no later command takes
- **Context**: The else shape first allowed ElseIf's optional `#color:` prefix.
- **Finding**: CommandActivityLong3 (registered later, ActivityDiagramFactory3.java:159) takes any `#color:...` line as a colored multiline activity. A head reject on `#red:else foo` would reject a valid activity. A keyword-prefix shape is exact only if every line it matches is either the family's or matched by no command at all.
- **Impact**: The else shape omits the color prefix; colored elseif outside an if is a gap (gap/colored-elseif-in-while). The test `test_shape_samples_reach_no_other_generated_command` checks samples, but the claim itself is per shape.
- **Confidence**: High

## Observation: kill/detach validity depends on the previous instruction
- **Context**: Probing kill placement.
- **Finding**: `kill`/`detach` fail on an empty list (InstructionList.java:169-174) and after start/stop/end/break/goto/label (each `kill()` returns false, e.g. InstructionStart.java:86-88, InstructionBreak.java:75-77). They succeed after an activity or spot, and after a closed if/while/repeat/fork/switch/split whose branches end killable. They also fail before the first case (InstructionSwitch.java:130-131 NPE via ProtectedCommand).
- **Impact**: Only the before-case form is modeled; the rest are gap fixtures (gap/kill-*). Exact modeling needs "last instruction kind" state per body.
- **Confidence**: High

## Observation: swimlane strategy needs state in every body context (for T21b)
- **Context**: FA nakavu/velodu/tmp1.
- **Finding**: The first activity-like command (activity, start, stop, end, if/while/repeat/switch/fork openers, spot, break; not split/goto/label) sets SWIMLANE_FORBIDDEN unless a swimlane came first (ActivityDiagram3.java:80-95). A later `|lane|` then fails anywhere, nested bodies included.
- **Impact**: T21b must double the body contexts (lanes-allowed / lanes-forbidden) or accept the FA. activity3.yaml documents how a structure model can shadow `a3_*` contexts through include order.
- **Confidence**: High (source; FA cases)
