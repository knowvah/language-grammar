## Observation: CommandPartition3 takes `group end`, so the legacy closer never sees it
- **Context**: head closer for `a3_group_body` copied from CommandCloseGroupLegacy3 (`(end ?group|group ?end);?`).
- **Finding**: CommandPartition3 is registered earlier (ActivityDiagramFactory3.java:110 vs :113) and matches `group end` / `group end;` as TYPE `group` + NAME `end`, so upstream opens a group named "end". CommandCloseGroupLegacy3 is reached only by `end group`, `endgroup`, `groupend` (+ `;`). A head copy without a guard popped instead and falsely rejected `group G` / `group end` / `}` / `}` (jar accepts). Caught by a test that checks copy samples against every earlier generated entry.
- **Impact**: any head entry (copy placed before the generated list) needs that check; keyword-prefix overlaps between "opener NAME" regexes and closers are easy to miss.
- **Confidence**: High (oracle-verified, pos/group-end-opens-a-group)

## Observation: the swimlane strategy is global state; only the top-level frame can carry it
- **Context**: FA nakavu/velodu/tmp1 (swimlane after the first activity).
- **Finding**: `swimlaneStrategy` (ActivityDiagram3.java:68-95) is decided by the first swimlane or "deciding" command (activity, spot, start/stop/end, break, and every opener except split, incl. startGroup). Openers push a body, so the frame below cannot change state on the same line. Modeled: undecided `a3_main` with head copies (`set`) of the swimlane and single-statement deciding commands; FORBIDDEN top level rejects swimlanes. Gaps (FA only): opener as first decider, late swimlanes only inside bodies, top-level `split` treated as ALLOWED. Exact modeling would need F-copies of every body plus opener copies per state (~45 copied entries).
- **Impact**: resolves all corpus swimlane FAs (each also has a late top-level swimlane). A model-level "global flag" mechanism would make this exact.
- **Confidence**: High (oracle probes; fixtures structure/{neg,gap}/swimlane-*)

## Observation: startGroup ignores the add result; notes never fail
- **Context**: probing groups and notes in every body.
- **Finding**: `partition P {` before the first `case` is accepted (ActivityDiagram3.java:425 ignores `current().add`), and activities inside go to the group's list. `addNote` fails only if `current().addNote` returns false, which no Instruction does at the pin; only unknown colors reject notes (NoSuchColorException).
- **Confidence**: High (oracle-verified)

## Observation: interpreter-only state heads roughly double Lark time on activity blocks
- **Context**: plantuml-ts `--lark sample --sample 100`: 6-11 timeouts per run (load average 150-280).
- **Finding**: A/B grammars from the same model/ and tools/ state, with and without T21b, on the oracle-preprocessed blocks. Groups alone are FASTER than the base (cakeca 1.5 s -> 1.0 s, judatu 16.4 s -> 13.1 s), because the group body replaces state-blind closers. The swimlane-strategy heads cost: tobajo 5.1 -> 11.5 s, dajuko 5.0 -> 9.5 s, bofaxe 51 -> 105 s, roroko 2.1 -> 4.1 s. Mechanism: each `set` copy in `a3_main` is an exit next to the generated rule, so Lark (unordered) starts one `a3_nolanes_main` root form per deciding line, and each runs to the block end. For Lark these paths are pure overhead: rejects are dropped, so the stay path already accepts the same text.
- **Impact**: `emit: false` (5834289) is now set on the 12 `set` heads of activity3-structure-lanes.yaml. A/B again (load ~300, mean of two runs), without -> with T21b: tobajo 5.4 -> 5.5 s, dajuko 5.5 -> 5.4 s, bofaxe 50.5 -> 51.0 s, roroko 1.9 -> 1.9 s. The cost is gone, and the interpreter slices have the same totals and cases. Any family that tracks diagram state with head copies should mark them `emit: false`. Keep the pop closers (group body) visible: their generated twins are rejects.
- **Confidence**: High (A/B repeated; absolute times noisy under load, ratios stable)
